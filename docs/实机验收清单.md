# 首轮实机验收清单

请分别记录源码版本、固件版本、设备 MAC 与测试终端型号。下面的硬件测试不由 GitHub Actions 自动完成。

## 首次启动

- LuCI、SSH 横幅与 ap8220-ap-status 中版本一致。
- 主路由可见唯一 AP8220 主机名与 DHCP 管理地址。
- 状态命令显示 product_info 出厂 MAC，br-lan 为该地址低 24 位加 1；重启及交换上联口后管理 MAC 不变，两台 AP 身份不同。
- 交换两个有线口上联，AP 与客户端仍能正常联网。
- 电脑接另一个口，取得主路由网段地址，默认网关指向主路由。
- AP 不额外发送 DHCP 租约、DHCPv6 地址或 RA。
- 主路由提供 IPv6 时，有线与无线终端均可获得对应 IPv6 连通性。
- 两个频段的 SSID、带宽、信道、国家码与本次编译参数一致；默认双频 Home-WiFi，1 / 36；无线密码与管理密码分别验证。
- 新装默认 Footstrap；检查登录页、主题设置、Turboacc 和 usteer 的简体中文，并验证手机浏览器布局及 Argon 切换。

## 原厂 stock 启动

- 串口日志显示 FIT 暂存 0x42000000、内核 Load Address 与 Entry Point 均为 0x44000000。
- initramfs 和写入后的系统均能进入 Linux，不再出现 new format image overwritten；分别记录冷启动和重启结果。
- 分区为 rootfs1、rootfs2 各 48MiB，usrdata 32MiB；记录实际 active 值及同布局升级行为，不将另一槽位视为已经实现自动回滚。

## 两台漫游

- 两台 AP 主机名和 NAS 标识不同。
- 对应 SSID、密码、加密方式与移动域相同。
- usteer 页面或 ubus call usteer remote_info 能看到另一台。
- 手机移动时 BSSID 能切换，记录丢包、语音中断与终端兼容情况。
- 旧设备异常时关闭对应网络的 11r 对照测试。
- 根据现场环境规划信道；不单凭相同 SSID 判定漫游正常。

## NSS 与可靠性

- Turboacc 页面存在，显示所选 NSS ECM 模式。
- 分别测试有线到无线、无线到有线吞吐和 CPU 占用。
- 检查 NSS/ath11k 相关日志，无持续崩溃、重启或掉线。
- 验证 HTTPS、SFTP 和诊断工具可用。
- 连续运行至少一个日常使用周期，记录异常。

## 升级与恢复

- 修改 SSID、信道和管理网络后，保留配置升级不会重置这些设置。
- 修改 root 密码后，保留配置升级不会改回出厂密码。
- 从旧版本升级后自动身份迁移生效，原有 SSID、信道、静态地址和主题保留；主路由 DHCP 地址保留更新到新的管理 MAC。
- 新版本 LuCI 和状态命令显示新的固件版本。
- 恢复出厂后重新应用该镜像默认设置。
- 已安装的 Web U-Boot 仍可进入，并能用于匹配镜像恢复。
